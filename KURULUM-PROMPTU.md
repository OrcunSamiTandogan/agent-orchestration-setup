# Shared setup instructions

Use these instructions after reading the explicitly selected scope from the [setup prompt](BASLA.md). Do not inspect, install, or configure unselected tools or providers.

1. **Inspect first.** Confirm this is the user's local computer, identify the OS, and read only its guide: [Ubuntu](docs/linux.md), [macOS](docs/macos.md), or [Windows](docs/windows.md). Check existing compatible installations before changing anything: a checkout is not proof that the launcher runs. In the app environment check `node -v`, `npm -v`, and `tmux -V` where needed. Pi needs Node.js 22.19+ and DSH needs Node.js 24.9+.
2. **Present a short plan.** Keep ordinary approvals and sandboxing. Don't install or overwrite anything until the user approves the specific change. Use the official [source ZIP](https://github.com/OrcunSamiTandogan/agent-orchestration-setup/archive/refs/heads/master.zip) in a fresh folder for a clean installation. Do not fall back to an old or unverified download, arbitrary script, or untrusted registry. If a platform prerequisite needs administrative approval, say exactly what it is and stop that step.
3. **Verify the chosen path.** Use the appropriate documented platform launcher. Check the actual installed launcher, not just the source files. Verify selected tool versions and, where possible, open the app and test the embedded terminal without a saved credential. For an isolated test, Pi's tmux session is `aa-pi` and DSH CLI's is `aa-evren-cli`; DSH Web has no tmux session. Do not attach to, interrupt, rename, or close existing sessions. Do not call a model during setup verification. If a test would need a real key, a preexisting sensitive profile, or a model call, skip it. Never read, request, store, echo, or send API keys; the user saves the relevant key directly in the masked app field. Do not push, deploy, or modify unrelated projects.
4. **Report only what you established.** Use **Component | Status | Evidence** with **Already ready**, **Installed**, **Needs attention**, or **Not verified**. Distinguish source/launcher checks, an actual GUI check, and a live response. Live provider response: **Not attempted**. Finish with one exact next action. Keep secrets, raw logs, or sensitive paths out of the report.
